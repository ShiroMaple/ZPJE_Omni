# 本地环境依赖与浏览器子代理鉴权边界准则

## 背景与事实确认

在近期版本迭代（如角色拓展与后台分配）的测试与验证过程中，曾出现耗时过长的情况。经复盘确认，核心原因包含以下两点客观事实：

1. **本地 Docker MySQL 服务未就绪导致的盲目重试**：
   * 本地代码在 `.env` 中配置连接 `localhost:3306` 数据库；当本地 Docker 托管的 MySQL 容器未处于运行状态时，本地测试和数据库写入操作必然失败。
   * Agent 未在首次连接被拒时立即向用户反馈，而是尝试自行排查或在本地与远端之间反复执行脚本试错，造成了不必要的冗长等待。

2. **浏览器子代理沙箱无法通过第三方 OA 单点登录获取管理权限**：
   * 门户管理后台（`/admin`）受致远 OA SSO 凭证与主域名 Cookie 保护。
   * 浏览器子代理运行于纯净的 Headless 沙箱环境中，缺乏 OA 系统的用户登录态、Cookie 以及内网单点登录跳转授权链路。
   * 尝试使用浏览器子代理访问受保护页面必然无法进入后台，导致子代理反复等待、超时甚至报 401 鉴权异常。

---

## 踩坑经验 (Lessons)

1. **本地基础设施端口阻断时，拒绝静默试错**：
   * 当工具或脚本报错 `ECONNREFUSED 127.0.0.1:3306` 时，根本原因是外部容器/宿主机服务未就绪，代码层面的重试或修改无法解决该问题。
   * 正确做法是：**第一时间中断本地测试流，直接向用户明确反馈“本地 Docker MySQL 容器未启动，请启动容器或指示在远程环境执行”**。

2. **识别浏览器子代理的鉴权边界**：
   * 凡是需要依赖企业内网第三方系统（如致远 OA SSO 票据交互、微信扫码登录、硬件加密狗等）完成身份签发的受限页面，浏览器子代理均无法凭空自动完成认证。
   * 严禁无预警地启动子代理去撞墙测试受保护页面，否则只会引发无意义的超时和长等待。

## 决策与行动准则 (Decisions)

1. **环境依赖即时提示原则**：
   * 在执行本地测试/数据写入前，先快速判断依赖端口（3306）可用性；若连接失败，**立即告知用户并等待确认**，不进行多轮静默重试。
2. **强鉴权受限页面测试规范**：
   * 对于强依赖 OA SSO 凭据的页面或接口：
     - 优先采用**后端单元测试、API 逻辑断言与服务端构建校验**；
     - 需要 UI 确认时，清晰提示用户在已登录 OA 的真实宿主浏览器中进行点击验收，明确告知用户当前已完成的代码改动与预期效果。
