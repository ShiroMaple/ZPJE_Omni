# 016 业务角色体系拓展与多角色分配管理系统

## 1. 业务背景与需求概述

随着建安万维统一门户系统的深入应用，各业务子系统对访问权限的精细化控制提出了更高要求。原有系统内置角色（系统管理员、高级操作员、普通员工）已无法完全覆盖“公司领导/分管领导”等专项业务审批与决策看板的权限隔离诉求。

同时，原有管理后台仅具备简单的“管理员特权分配”功能，缺乏对 6000+ OA 在职员工进行业务角色自由配置与多角色组合分配的能力。

本次开发完成了以下目标：
1. **数据模型与枚举扩展**：在数据库角色体系中拓展“领导”角色（Key: `leader`，Name: `领导`），与系统管理员、高级操作员、普通员工并列。
2. **管理后台功能整合与升级**：将原“管理员分配”升级为“权限与角色分配”，支持“业务角色分配”与“管理员特权分配”双子标签页分级管理。
3. **多角色支持与即时分配**：员工支持同时分配多个角色（如“高级操作员 + 领导”），提供检索即选即生效的极速交互体验。
4. **分级权限管控与审计追踪**：系统管理员与运维管理员均可管理业务角色；管理员特权分配严格保留给系统管理员；角色变更全量写入 `ROLE_MANAGE` 审计日志。

## 2. 核心架构与设计

### 2.1 数据库角色定义与映射
| 角色唯一键 (Key) | 角色名称 (Name) | 标识样式 | 适用场景 |
| :--- | :--- | :--- | :--- |
| `admin` | 系统管理员 | 红色 (Red) | 拥有全系统配置、特权分配、全部应用访问权 |
| `operator` | 高级操作员 | 蓝色 (Blue) | 生产、运营核心子系统的主力操作人员 |
| `leader` | 领导 | 琥珀黄 (Amber) | 领导专用决策看板、跨部门审批与核心统计应用 |
| `user` | 普通员工 | 翡翠绿 (Emerald) | 组织内全体在职员工默认业务角色 |

### 2.2 RBAC 权限判定流
门户系统采用基于角色的访问控制（RBAC）：
- 门户首页抓取当前登录用户在 `MemberRole` 关联表中的所有有效角色。
- 只要目标应用配置的权限列表包含用户的任一有效角色，该应用即对用户开放展示与免密访问。

## 3. 后端 API 与鉴权改造

### 3.1 鉴权层（`lib/auth.ts`）
新增 `checkOpsAdminOrAbove()` 方法，允许 `SYS_ADMIN` 与 `OPS_ADMIN` 进入业务角色管理模块，实现安全且合理的权限下沉。

### 3.2 成员与角色接口（`app/api/admin/members/route.ts`）
- **`GET /api/admin/members?type=roles_data`**：
  - 查询所有已被授予至少一个业务角色的员工列表，预加载部门、单位与角色明细。
- **`GET /api/admin/members?search=xxx`**：
  - 支持按姓名、工号、拼音、账号实时模糊匹配员工，并附带该员工当前的全部角色关联。
- **`PUT /api/admin/members`**：
  - 支持传入 `roleIds: string[]`，使用 Prisma `$transaction` 保证“全删 + 全插”的幂等原子更新。
  - 自动触发 `recordSystemLog(operator, 'ROLE_MANAGE', '为成员 xxx 分配业务角色：xxx')`，确保权限变更有迹可查。

### 3.3 审计日志层（`lib/audit.ts`）
扩展 `actionType` 枚举，加入 `'ROLE_MANAGE'`，并在管理后台的“审计与统计”日志筛选器中增加对应中文类型与徽章渲染。

## 4. 前端交互与视觉设计（`AdminAppRegistry.tsx`）

1. **左侧导航栏整合**：
   - 菜单项更名为 **“权限与角色分配”**，图标保持盾牌（`Shield`），系统管理员与运维管理员均可见。
2. **子标签页布局**：
   - **业务角色分配**：默认视图，运维管理员与系统管理员可用。
   - **管理员特权分配**：仅系统管理员可见，避免特权提权风险。
3. **角色汇总看板**：
   - 顶部提供 4 个角色的人数统计卡片，点击可快捷按角色筛选员工列表。
4. **极速检索与分配面板**：
   - 左侧输入姓名/工号/账号检索（带防抖 `useRef`），结果展示员工卡片与 4 个角色的多选标签按钮，点击即时触发变更。
   - 右侧表格汇总已分配角色的员工，支持关键词过滤、角色筛选与单角色的快捷“×”一键移除。
