# 阶段性开发总结与 Agent 交接规则 (Auto Doc & Handover Rule)

## 1. 触发条件 (Trigger Conditions)
在当前会话中，当你（Agent）遇到以下任意情况时，**必须主动**执行文档编制流程：
1. 完成了一个相对独立的开发阶段、核心功能模块实现、重大 Bug 修复或代码重构。
2. 感知到当前会话的上下文（Context Window）较长、即将达到上限或即将切入新任务。
3. 用户明确发出“阶段总结”、“交接”或“准备新会话”等指令。

## 2. 存储路径与命名规范 (Location & Naming)
- **存储目录**：项目根目录下的 `docs/`（若目录不存在，请自动创建）。
- **文件命名**：`{三位编号}_{短标题}.md`（例如：`001_auth_jwt_login.md`、`002_fix_db_deadlock.md`）。
- **编号计算**：
  1. 检查 `docs/` 目录下已存在的最大编号（如 `003_xxx.md`）。
  2. 新文档编号在此基础上递增（即 `004`）；若无历史文档，则从 `001` 开始。

## 3. 文档生成模板 (Markdown Template)
新建文档时，必须包含以下结构：

# 开发总结：{任务简述}

- **归档日期**：{YYYY-MM-DD}
- **涉及模块/文件**：{修改或新建的关键文件列表}
- **阶段状态**：{已完成 / 部分完成}

- **遇到问题**：{遇到的报错、概念理解偏差或环境阻碍}

- **避坑提示**：{特别提醒后续 Agent/开发者“切勿修改某处”或“必须注意某个隐蔽逻辑”}

## 4. 下一步交接指引 (Handover Notes)
- [ ] {未尽事项或需后续验证的点 1}

- **关联依赖**：{接手时需要先阅读的相关文件或运行的命令}

## 4. 执行流程 (Execution Steps)
1. 检查 `docs/` 目录并确定新的文件编号 `{编号}`。
2. 提取本会话的主要改动、排错经验与交接信息。
3. 调用文件写入工具创建并保存 `docs/{编号}_{标题}.md`。
4. 保存成功后，在对话中简要回复用户：“已自动为您生成开发交接文档：`docs/{编号}_{标题}.md`”。
